# Project Reflection

**Design Decision:** I kept the actual math out of the LLM's hands for the loyalty discount calculator and handed it off to the AgentCore Code Interpreter instead. The discount builds up in stages, each step feeding the next: first you cap the points a customer can redeem, then apply the tier discount on top, and finally work out how many points they earn on the adjusted subtotal. That chained, order-dependent arithmetic is exactly where models tend to slip, and a small rounding mistake would compound across the steps. Running a short Python script inside a locked-down sandbox gave me consistent numbers on every run plus an audit trail - something that matters when the output decides what a customer actually pays. I also wired in a fallback to a simple tier-only discount whenever the Code Interpreter can't be reached, so the tool bends instead of breaking.

**Challenge:** Most of my time went to IAM permission errors that never showed up locally and only surfaced once I deployed to AgentCore Runtime. To chase them down, I ran `aws logs filter-log-events` against the deployed agent's CloudWatch log group after each failed call, which handed me the exact exception: an `httpx.HTTPStatusError` reading "403 Forbidden" on the Gateway MCP endpoint. That pointed at the execution role rather than my code - my local CLI credentials were wide open, but the auto-generated role started with essentially nothing. So I ran `aws iam put-role-policy` to grant `bedrock-agentcore:InvokeGateway` scoped to the specific gateway ARN, re-ran `agentcore invoke`, and watched the 403 disappear as the order-tracking tool returned the right tracking number. I then walked through the same diagnose-fix-verify loop for the Knowledge Base (`bedrock:Retrieve`) and the Browser Tool (`bedrock-agentcore:StartBrowserSession` on the `browser/aws.browser.v1` ARN).

**Production Consideration:** For production, I'd set up CloudWatch alarms on Gateway 4xx/5xx rates and on Code Interpreter execution failures, since these tools fail quietly - the Browser Tool, for example, returns a polite error message rather than throwing an exception - and that hides genuine problems from users and operators. I'd also pull the Knowledge Base ID and Gateway URL out of hardcoded constants and into environment variables or SSM Parameter Store, so endpoints and credentials can be rotated without shipping a fresh deploy.
